# 03 种子酒店试用方案(MVP 验证)

> 用途:第 7-8 周,从访谈的酒店中选 2-3 家免费试用,验证工具真实可用性,收集反馈迭代。
> 前置条件:访谈阶段收集到至少 2 份真实账单样本,解析器已按真实格式适配。

## 一、试用目标与成功标准

| 目标 | 成功标准 |
|---|---|
| 工具能处理真实账单 | 3 家酒店都能完整跑通「上传→对账→导出」,无崩溃 |
| 发现真实差异 | 至少 1 家酒店试用中查出 ≥1 笔账实不符(哪怕 50 元) |
| 反馈可执行 | 每家给出 ≥3 条具体反馈(痛点/改进/价格) |
| 付费意愿复验 | ≥2 家试用后愿意为工具/服务付费(记录可接受价格) |

## 二、种子客户筛选(从访谈名单中选)

1. 优先选 **每月对账 ≥ 1 天**、老板本人参与对账的酒店(决策人直接体验,反馈最真实)
2. 优先选 **携程或美团订单量大的**(月订单 ≥ 100 单,工具价值才体现)
3. 避免选:连锁品牌店(决策权不在店长)、对电脑操作抵触的纯老板娘店(除非老板在场)

## 三、现场演示脚本(30 分钟)

| 时间 | 内容 |
|---|---|
| 0-5 min | 演示前聊天:上次访谈提到的问题(如"No-show 扣佣"),建立"我是来解决这个的"认知 |
| 5-10 min | 安装/启动工具(双击 exe 或 run_dev.bat),导入对方的真实渠道账单 + PMS 导出 |
| 10-15 min | 跑对账,展示四类结果;**重点看"差异"和"单边"两类**,当场读出问题单 |
| 15-20 min | 导出差异报表,演示怎么交给财务/代账 |
| 20-30 min | 让**对方自己操作一遍**(关键!老板/前台亲手点),观察卡点,收集反馈 |

## 四、反馈收集表(试用后 24 小时内填写)

| 维度 | 问题 | 记录 |
|---|---|---|
| 上传 | 账单/PMS 导出格式是否顺利?卡在哪一步? | |
| 对账 | 结果是否看得懂?有没有误判/漏判? | |
| 价值 | 这次对账查出了什么问题?省了多少时间? | |
| 价格 | 如果付费,愿意出多少?买断还是按年? | |
| 建议 | 最想要的下一个功能? | |

## 五、试用注意事项

1. **数据脱敏**:演示用的账单如含客人姓名,可先告知"仅在本机处理,不留存";工具本地部署天然满足
2. **不承诺做不到的**:解析器对未知格式会报错,如实说"这个格式下个版本支持",记录格式回传
3. **试用期 2 周**,结束当天明确下一步:付费 / 继续观望 / 不感兴趣(记录原因)
4. 每家酒店试用结束,**收集对方的账单导出格式样本**(打码),用于扩充解析器

## 六、首轮迭代优先级(按反馈排序)

1. 真实账单格式适配(最高优先——解析不了,一切都白搭)
2. 解析报错信息更友好(告诉用户"哪一列没识别出来")
3. 新增高频渠道(飞猪/抖音酒旅)
4. 差异报表更贴近财务口径(加酒店抬头、对账周期)
5. 多期账单合并对账(月度汇总)

> 迭代原则:每收一轮反馈,只做最痛的 1-2 项,做完立刻回访展示,形成「试用→反馈→迭代→再演示」闭环。
